# 창 경로와 전이 함수 선택

## 사용

- 내부 StateMachine 탭은 `루트이름/Layer이름/StateMachine`을 표시한다. 예: `SampleGraph/Layer1/StateMachine`.
- State Pose 탭에는 그 뒤에 State 이름도 표시한다. 탭 폭이 좁으면 마우스를 올려 전체 경로를 확인한다. Layer 이름을 바꾸면 표시 경로도 갱신된다.
- StateMachine 툴바의 **Transition Conditions**, 또는 **Window → UAnimGraph → Transition Conditions**를 연다.
- 일반 State 간 연결의 **Choose function…**을 누르고 함수 이름을 검색해 선택한다. **Open function source**로 코드를 연다.
- 함수 선택은 GTK의 실제 Rule/Condition에 저장하며 Undo/Redo와 루트 내부 저장을 지원한다. 기존 Duration/Priority는 유지하며, 함께 사용할 수 없는 Parameter/Exit Time 조건은 함수 선택 시 대체한다.

스크린샷의 Entry → Pose State는 조건부 전이가 아니라 시작 State 지정 연결이다. 이 연결에는 전이 함수를 지정하지 않는다. Pose State를 하나 더 만들고 두 State 사이를 연결한 후 해당 전이의 함수를 선택한다.

GTK는 ITransition.AddRule, Condition<T>, ConditionView<T>를 공개 API로 지원한다. 따라서 Transition 자체를 대체할 필요 없이 네이티브 GTK 데이터와 연결되는 선택 패널을 제공했다.

공식 문서: [ITransition](https://docs.unity.com/en-us/engine/7000.0/script-reference/unity/graphtoolkit/editor/itransition), [ConditionView](https://docs.unity.com/en-us/engine/7000.0/script-reference/unity/graphtoolkit/editor/conditionview1).

## 검증

Unity 7000.0.0a9의 별도 프로젝트에서 신규 자동 검사 12개, 기존 통합 41개와 기본 회귀 33개·루트 연결 검증을 통과했다. 경로 계산·창 제목/툴팁 설정·Layer 이름 변경, Entry 제외, 함수 선택 저장/재열기, 시간/우선순위 보존, 호환되지 않는 필드 조건 교체, 런타임 정의와 루트 서브에셋 반영, 독립적인 Undo/Redo를 확인했다. 로그: `.validation-project/Logs/TransitionUi3.log`, `UAnimGraph-transition-ui-verification.txt`.

자동 검사는 공개 API와 같은 데이터 변경 경로를 실행했다. 이번에는 사용자 Unity 창의 마우스 조작·탭 표시 화면을 직접 검사하지 않았다.
