# 컴파일 경고 정리

Unity 7000.0.0a9에서 전체 스크립트 캐시를 비우고 재컴파일해 확인했다. 고유 컴파일 진단은 **88개 → 0개**, 최종 컴파일 오류도 **0개**다.

## 수정

- 구형 FindObjectsByType 정렬 인자를 제거하고 현재 API를 사용한다.
- 전이 함수 검색은 AppDomain.GetAssemblies 대신 Unity가 관리하는 CurrentAssemblies.GetLoadedAssemblies를 사용한다.
- 편집기 캐시·비동기 검사 상태에 NoAutoStaticsCleanup을 멤버별로 명시한다. 편집 세션 상태는 Play Mode 전환으로 비우지 않으며 기존 편집기 종료·해제 콜백이 수명을 관리한다.
- 런타임 전이 함수 캐시는 기존 SubsystemRegistration 초기화를 유지한다. Animator 소유권은 기존 인스턴스 Dispose 수명을 유지한다.
- GTK 샘플의 네 싱글턴은 기존 Awake/OnDestroy의 Instance 설정·해제를 유지하도록 해당 속성에만 NoAutoStaticsCleanup을 표시한다.
- Rider 3.0.38은 프로젝트 로컬 임베디드 패키지로 포함했다. 세 C# 파일에서 Unity 7의 어셈블리 목록·경로·로딩 API를 사용하며 이전 Unity 버전용 코드는 전처리 분기로 보존한다. 의존성 버전과 기능 구성은 변경하지 않는다.
- Rider 편집기 어셈블리에만 UAL0010/UAL0013을 제한한다. IDE 캐시와 테스트 세션은 Play Mode와 별도 수명을 가진다. 규칙 파일은 Packages/com.unity.ide.rider/Rider/Editor/com.unity.ide.rider.ruleset이다. 프로젝트·런타임 어셈블리의 진단은 계속 켜져 있다.

패키지 캐시를 직접 수정하거나 전역 nowarn 옵션을 추가하지 않았다. Rider 패치를 갱신할 때는 임베디드 패키지의 LOCAL_PATCH.md를 참고한다.

## 검증

- 클린 컴파일: 경고 0, 오류 0, 종료 코드 0.
- State 자동 생성 14개, Layer/Machine 10개, 내부 저장 14개, 전이 UI 12개와 통합 41개·기본 회귀 33개·루트 연결 검증 통과.
- 실제 프로젝트의 다른 C# 소스도 검증 복제본과 일치함을 확인했다.
- 로그: Logs/WarningsZeroClean.log, Logs/WarningsRegression.log. 원본 진단: Logs/WarningBaseline.log.

씬·클립·사용자 그래프는 수정하지 않았다. 누락 Clip 같은 저작 데이터 진단은 컴파일 경고와 별개이며 계속 보고한다. Rider IDE 자체와 연결한 디버거·테스트 러너 세션은 직접 실행하지 않았다.
